# VPRune

Official code for our paper [**VPRune: Efficient Training-free Pre-LLM Visual Token Pruning**](https://arxiv.org/abs/2609.24485).

**Training-free visual token pruning for FastVLM: visual-only diversity selection, position preservation, and similarity-guided token recycling.**

This standalone research implementation contains the final VPRune method. It runs independently of the original experimental repository. Baseline pruning methods, training controllers, private data, server configurations, and model weights are excluded.

## Method

`Image → FastViT-HD → Projector → VDS → STR → PPR position IDs → Qwen2 LLM`

- **VDS — Visual-only Diversity Selection** normalizes post-projector visual features, constructs a cosine Gram kernel, and selects complementary features using greedy DPP MAP inference. Selection uses no text-relevance term or visual attention/saliency weighting.
- **PPR — Position-Preserving Restoration** keeps retained tokens in their original sequence order and preserves their original position IDs. Text after the image and generated tokens retain the positional span of the unpruned sequence.
- **STR — Similarity-guided Token Recycling** assigns each discarded token to its most similar retained token using cosine similarity. A softmax within each destination group weights the discarded features before fusion. Retained tokens with no assigned sources remain unchanged. Similarity is defined in feature space, rather than by 2D spatial proximity.

The default configuration is `budget=0.3, gamma=0.3, tau=0.1`. The token budget is configurable; VDS and PPR remain enabled in the final method.

```text
K = max(1, min(N, round(budget * N)))
L[i,j] = cosine(x[i], x[j])
S ≈ argmax_{|S|=K} log det(L[S])       # greedy incremental Cholesky
owner(i) = argmax_{j∈S} L[i,j]
w[i,j] = softmax_{i∈G[j]}(L[i,j] / tau)
fused[j] = (1-gamma)*x[j] + gamma*sum_{i∈G[j]} w[i,j]*x[i]
visual_position[j] = N_prefix + original_index[j]
first_suffix_position = N_prefix + N
```

`round` follows Python's rounding semantics, not floor. For N=256, budgets of 0.1/0.3/0.6/0.8 retain 26/77/154/205 tokens, respectively. PPR does not insert placeholder tokens: the actual input contains only K visual vectors. STR updates feature vectors without reconstructing image pixels or changing position IDs. The fusion formula applies to nonempty destination groups; an empty group leaves its retained feature unchanged.

## Install

Python 3.10 or 3.11 is recommended. Core dependencies are pinned to PyTorch 2.6.0, Transformers 4.48.3, and timm 1.0.15 to keep the custom model implementation compatible and reproducible.

```bash
python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .
python -m unittest discover -s tests -v
```

For CUDA, install PyTorch 2.6.0 and torchvision 0.21.0 builds compatible with your driver. CPU and Apple MPS default to float32; CUDA defaults to float16. On the tested Mac, MPS float16 produced NaNs in the first Qwen2 layer, while float32 ran successfully. The generation code raises an error on non-finite logits.

MPS does not support float64, so the small VDS/STR stage runs on CPU while the model remains on MPS. This compatibility path should not be used to reproduce the paper's device-latency measurements.

## Run one image

```bash
python examples/create_demo.py
python -m vprune \
  --model apple/FastVLM-1.5B \
  --trust-remote-code \
  --image examples/demo.png \
  --question "What color is the circle? Answer with one word." \
  --budget 0.3 --gamma 0.3 --tau 0.1 \
  --max-new-tokens 16 \
  --output runs/demo.json
```

You can use the `vprune` command instead of `python -m vprune`, and replace `--image` with your own image. The question is passed through unchanged: the runner does not alter capitalization or append evaluation instructions. The demo image is generated by this project's script and contains no third-party dataset content.

The command loads official pretrained weights and runs visual encoding, projection, VPRune, LLM prefill, and greedy decoding. Its JSON output includes the answer, visual token counts before and after pruning, retained indices, position IDs, the number of updated features, and software versions. The reported single-run time is a diagnostic measurement, not a latency benchmark.

**Verified example (November 2, 2026):** in an isolated environment using the pinned official 1.5B checkpoint, the demo image contains a red square and a blue circle. Both CPU float32 and MPS float32 answered `blue` to the question above, with 256 visual tokens reduced to 77, VDS/PPR enabled, gamma=0.3, and tau=0.1. Run the regression suite with `python -m unittest discover -s tests -v`. This example verifies the inference pipeline on a simple original image; it is not a TextVQA or GQA accuracy result.

### Checkpoints and upstream code

Two official Hugging Face checkpoints are supported, with the following immutable default revisions:

- `apple/FastVLM-1.5B`: `dd6608dfa0e17b050e1dde2856c3437fcba197ac`
- `apple/FastVLM-0.5B`: `16375720c2d673fa583e57e9876afde27549c7d0`

The first run downloads the weights to the Hugging Face cache. `--trust-remote-code` explicitly authorizes execution of the official FastVLM custom model code; review the pinned revision before enabling it. Loading is refused without this flag. The loader accepts supported official Hub repositories and immutable revision SHAs, rather than arbitrary third-party repositories or a moving `main` branch.

For offline inference, cache the official model first and add `--local-files-only`, or use `--model /path/to/complete/hf/snapshot`. A local snapshot must contain the full weights, tokenizer, configuration, and `llava_qwen.py`. A directory containing only configuration and tokenizer files is insufficient. This release does not directly support checkpoints with experimental controllers or LoRA adapters, and it rejects weight-loading mismatches.

Do not assume that official Hugging Face checkpoints and custom checkpoints used in historical experiments have identical weights without verification. The local smoke test verifies the pipeline and does not establish reproduction of all paper accuracy results. Device, precision, and numerical ties can affect DPP selection and generation.

## Python API

```python
from vprune import VPRuneConfig, prune_visual_tokens
from vprune.inference import generate

config = VPRuneConfig(budget=0.3, gamma=0.3, tau=0.1)
# Post-projector features: [1, N, D]
result = prune_visual_tokens(visual_features, config)
# An already loaded official FastVLM model, prompt with one image placeholder:
generated = generate(model, input_ids, pixel_values, config,
                     max_new_tokens=16, eos_token_id=tokenizer.eos_token_id)
```

The runner supports one image, batch size 1, the official square-padding preprocessing, and greedy decoding. Multi-image inputs, video, beam search, dynamic-resolution tiling, training, and a full benchmark evaluation framework are outside this release's scope.

Set `gamma=0` to disable STR while keeping VDS/PPR enabled. At `budget=1`, all visual tokens are retained and STR leaves their features unchanged because there are no discarded sources. `tau` must be at least `1e-6`: the research implementation silently clamped smaller values, while this release rejects them so the reported parameter matches the computation. Mixed-precision GPU scatter accumulation can introduce rounding differences; bitwise reproducibility across devices is not guaranteed.
